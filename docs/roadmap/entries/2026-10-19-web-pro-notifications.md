- 🟡 **Web Pro — le salon a enfin ses notifications sur le web : `/pro/notifications`, le nombre de non-lus sur l'entrée de navigation et sur la cloche du téléphone, rafraîchi toutes les 60 s tant que l'onglet est visible ; reste la CI (web, 2026-10-19).** ([web-pro-notifications.md](../../design/web-pro-notifications.md)) **Le manque** : le serveur écrit un fil pour chaque membre d'un salon (nouvelle réservation, report, annulation, justificatif d'acompte) et `GET /me/notifications` sert une session Pro — mais le web Pro n'avait ni page, ni cloche, ni compteur : un salon qui travaille sur PC ne voyait jamais qu'un client venait de réserver. **Maintenant** : une entrée « Notifications » juste après « Aujourd’hui » (tous les rôles) et une cloche dans la barre du haut mobile, chacune avec une pastille et un nom accessible qui porte le nombre ; le fil relu toutes les 60 s **seulement onglet visible** et aussitôt au retour ; l'arrivée annoncée poliment (par identifiant — jamais au premier chargement, jamais pour une ligne remise non lue) ; le titre d'onglet « (3) … ». La page : chaque ligne est un **lien** vers le rendez-vous avec son salon, lue au clic (et remise non lue en disant pourquoi si le serveur refuse), « Tout marquer comme lu », les quatre états, le nom du salon sur chaque ligne pour un compte à plusieurs salons. Le détail **bascule de salon** quand `?salon=` en nomme un autre — le flux de l'app. **Trouvé dans le navigateur et corrigé** : la sonde `/me` partie avant une bascule répondait après et remettait la barre latérale sur l'ancien salon pendant que le serveur agissait pour le nouveau ; une bascule retire désormais toute sonde antérieure et termine elle-même le chargement (le premier correctif oubliait ce point — le test l'a vu). **Aucun changement serveur.** **Vérifié ici** : typecheck, lint, 1 622 tests unitaires web verts ; le parcours dans le navigateur sur le bouchon e2e, à 1280 et 375 px. **Ordre** : à fusionner après #640 et à déployer après son serveur (l'état vide nomme les « reports »).
