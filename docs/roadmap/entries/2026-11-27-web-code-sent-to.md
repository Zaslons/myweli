- 🟢 **Le site : l’adresse e-mail de l’étape du code sur sa propre ligne, coupée seulement à ses jointures (web · 2026-11-27, la forme de l’app #895, [web-code-sent-to.md](../../design/web-code-sent-to.md)).** Branche `fix/web-code-sent-to-address`, créée depuis `main` (`da6e947b`), sur l’accord du propriétaire (« Approved, build it ») donné au plan mesuré. Règle : [WEB-SYSTEM.md](../../design/WEB-SYSTEM.md) §9, §15 ligne 39.
  - **Mesuré avant de construire** (le stub, Chromium à 320×568, la police Hanken Grotesk du dépôt, la même sous Linux). Le défaut du site n’est pas celui de l’app : un navigateur ne coupe jamais au milieu d’un mot, donc l’adresse n’était jamais coupée, elle débordait. Au texte agrandi à 200 % façon Android, la page devenait plus large que le téléphone : 408 px pour `aminata.kone@exemple.ci`, 483 px pour `awa.kone.nouvelle@exemple.ci`, sur les deux connexions (et sur la connexion du tunnel de réservation, le même composant). Au texte normal, l’adresse passait déjà seule à la ligne, avec un point dessiné. Aucun test n’atteignait cette étape.
  - **Les coupures comparées :** `overflow-wrap` seul coupe n’importe où (« aminata.kone@exe » / « mple.ci », « koffi.yao@gmail.co » / « m ») ; un `<wbr>` avant le « @ » et avant chaque « . » de la partie nom donne « aminata.kone » / « @exemple.ci » ; un `<wbr>` dans le domaine laisse « .com » seul ; l’adresse laissée dans la phrase commence sur la ligne de « à ». Retenu : les `<wbr>`, avec `break-words` seulement pour un morceau plus large qu’une ligne.
  - **Ce qui change :** `CodeSentTo` dessine la phrase, puis l’adresse sur sa propre ligne, à l’encre, sans point ; `emailSeams` (`lib/format.ts`) la découpe à ses jointures. Un lecteur d’écran entend la même phrase qu’avant, d’un seul tenant, point compris (une copie masquée ; le dessin lui est caché). Copier l’adresse donne l’adresse propre : un `<wbr>` ne se copie pas. La ligne 99 de SYSTEM.md (#895), qui comptait les deux connexions du site parmi ce qui n’est pas couvert, renvoie ici.
  - **Rouge d’abord,** sur le code de `main` : 16 tests unitaires sur 24 (chaque test du dessin, sur les deux connexions ; les 8 du lecteur d’écran passaient, comme ils le doivent) et les 12 cas e2e (le mode Android sur la largeur, 408 et 483 px ; les deux autres modes sur le point dessiné).
  - **Mutations, sur le code commité :** 15 au niveau unitaire et 5 sur le bloc e2e (chacune reconstruite), toutes rouges. Deux avaient d’abord survécu, et chacune a appris quelque chose au garde-fou. Sans `.trim()`, tout restait vert : un champ `type="email"` retire lui-même les espaces, donc la ligne tapée avec des espaces n’atteignait pas le composant ; un test direct la tient. Sans `break-words`, le bloc e2e restait vert : aucune de ses adresses n’avait un morceau plus large qu’une ligne ; `ouattaraaminatakone@exemple.ci` s’y ajoute, et sans le dernier recours la page s’élargit (332 px).
  - **Vert sur la branche :** les 18 cas e2e (trois adresses) ; `type-overflow`, `axe`, `focus`, `tap-targets` et `favorite-after-sign-in` (199 tests) ; un passage d’axe sur les deux étapes du code, propre.
  - **Reste ouvert :** quatre autres endroits du site dessinent une adresse, non mesurés ici — la liste de l’équipe, le menu Pro et le profil du salon (`break-all`, qui coupe n’importe où), et `support@myweli.com` des pages légales, coupé après son « @ » (pages gelées).
