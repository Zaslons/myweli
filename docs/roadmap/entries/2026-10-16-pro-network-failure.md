- 🟢 **Pro web — une coupure réseau n'est plus un chargement éternel ; chaque enregistrement rend la main, la Journée sait échouer (web, 2026-10-16).** ([web-pro-network-failure.md](../../design/web-pro-network-failure.md)) **Le défaut** : les 45 appels de `lib/api/pro.ts` faisaient un `fetch` nu (seul `logoutPro` l'attrapait) et douze lisaient le corps d'un 2xx sans filet ; une coupure rejetait jusqu'au chargement de la page, que personne n'attrapait — 15 pages Pro restaient sur leur squelette pour toujours, sans message ni « Réessayer », et aucune frontière d'erreur ne le voyait. Les enregistrements restaient « occupés » : la fenêtre « Modifier le numéro » d'une fiche client, qui ne se ferme pas pendant qu'elle enregistre, enfermait le salon ; la connexion, l'export, le bouton photo (la signature du téléversement) tournaient pour toujours. **La décision** : à la racine, pas quinze `try/catch` — les wrappers ne lèvent plus (`send()` → `Response.error()`, statut 0 ; `readJson()` → un corps 2xx illisible est le statut 0 pour une lecture, jamais une liste vide inventée), et la branche « pas 200 » que chaque page a déjà est son état d'erreur. L'audit de chaque appelant : 401, 403 `not_a_member` et les 404-états (pas encore d'offre, fiche introuvable) sont intacts ; trois appelants changent — la carte d'invitations garde « Pas de connexion. Réessayez. », la connexion Pro le dit au lieu de « Code incorrect ou expiré. » sous le champ. **La Journée**, vue par défaut des rendez-vous, ne savait pas échouer du tout : un 500 laissait aussi le squelette, et un changement de jour raté gardait la grille de la veille sous la nouvelle date — elle a son état d'erreur et « Réessayer », comme l'app. **Vu rouge** : la table de chaque export (84 cas rouges sur 125), les 16 pages (27 cas, chacun sur son squelette avec un rejet non géré), les enregistrements (5), la Journée (3), la signature (3) ; les deux tests existants de la carte d'invitations sont tombés rouges sous le changement racine seul, comme l'audit l'avait prévu. **Dépend de #616** : sur `main`, l'Acompte lit encore une lecture ratée comme une politique vide ; la ligne Acompte de la table ne passe qu'avec lui. **Hors périmètre, consigné** (§9) : « Pas de connexion » au lieu de la phrase générique sur les lectures ; le web client (`lib/api/account.ts`, 17 `fetch` nus) ; les lectures secondaires qui restent silencieuses. **Déploiement** : le web au merge, après #616 ; rien côté serveur.
