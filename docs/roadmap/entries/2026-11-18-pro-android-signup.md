- 🟡 **L’app Pro Android inscrit de nouveau les salons ; l’app iPhone n’en porte rien (app · 2026-11-18 — BACKLOG B0.10, B0.17, PR B ; décisions 116 à 123).** Non fusionné : branche `feat/pro-android-signup`, créée depuis `main` (`d0b2c85a`). L’étape 3a d’[android-play-release.md](../../design/android-play-release.md) §4, la deuxième des trois PR de [pro-android-signup.md](../../design/pro-android-signup.md) §9.1, derrière la clôture de la PR A (#806).
  - **Pourquoi :** sur Google Play, un salon qui trouve MyWeli Pro doit pouvoir créer son compte dans l’app ; c’est aussi ce qui rend possible le test fermé avec des testeurs payés, qui n’ont pas d’invitation. Apple l’a refusé deux fois (3.1.1) : l’app iPhone reste en connexion seule.
  - **Ce qui change, sur Android seulement :** au bas de la connexion, « Pas encore de compte ? » et « Créer le compte de mon salon » (ou, après « Aucun compte MyWeli Pro… », cette phrase et le même bouton). La page « Créer mon compte » demande d’abord le salon (le nom, le type sans valeur par défaut, le téléphone, l’adresse, la commune facultative), puis l’identité (Google ou un code e-mail ; le code déjà reçu à la connexion est repris). Avant toute création, l’app essaie une connexion avec cette identité : un compte existant est connecté sans rien créer, des invitations s’affichent avec « Créer plutôt mon propre salon », et sinon le compte et son salon en brouillon sont créés. Ensuite, « Accueil » et la carte « Configurer mon profil », comme pour un salon créé sur le site. Aucun prix, aucune offre, aucun essai sur ce parcours.
  - **Ce qui ne change pas :** l’app iPhone. Les pages vivent derrière la clôture de la PR A ; les appels de création sont dans le code partagé, mais rien côté iPhone ne les appelle, et le compilateur les retire. Aucun changement backend, contrat ni déploiement.
  - **Les garde-fous :** les mots de l’inscription Android sont absents du code de l’app iPhone et présents dans celui de l’app Android ; la lecture du binaire iPhone (app-store-forms §11.3) passe de 14 à 40 phrases à 0 ; les appels de création ne sont appelés que derrière la clôture ; aucun prix ni offre dans le dossier clôturé ; chaque état du parcours a son test, aux trois largeurs et à 200 % de texte. 40 mutations, toutes rouges. Un build iPhone non signé de la branche se lit `OK : 40 phrases à 0, 6 témoins présents`, sans `/pro/register` ni `/auth/provider/register` ; le même build depuis l’entrée Android échoue sur les 27, comme il le doit. Les 60 captures existantes sont identiques à l’octet ; cinq nouvelles.
  - **Reste :** la PR C (les documents et les textes Play), avant l’étape 7 ; à l’étape 5, la lecture des mêmes phrases dans l’AAB (présentes) ; les passages sur appareil (lignes 11 à 16).
