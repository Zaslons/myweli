- 🟢 **Pro web — réservation manuelle comme l'app : « Client sans numéro » réserve un client de passage sans nom ni numéro ; un nouveau client a sinon besoin d'un numéro (web, 2026-10-20).** ([web-manual-booking-walk-in.md](../../design/web-manual-booking-walk-in.md)) **Le constat** (audit de parité §4, P2) : le web exigeait un nom et laissait le numéro facultatif ; l'app fait l'inverse — numéro obligatoire sauf « Client sans numéro », nom facultatif — et le commentaire du web disait « comme l'app ». Un client de passage dont on ne sait rien ne pouvait pas se réserver sur le web. **Ce qui change** (décision du propriétaire : comme l'app) : le numéro est demandé pour tout nouveau client (il n'apparaissait qu'après un nom tapé) ; la case « Client sans numéro » le désactive, efface son erreur et n'envoie rien ; le nom est facultatif (le rendez-vous s'affiche « Client », comme dans l'app) ; « Créer » ne dépend plus du nom, le numéro manquant se dit sous son champ (« Saisissez un numéro de téléphone. »). Les trois portes du dialogue (« + Nouveau rendez-vous », la grille, la fiche client) en profitent ; aucun changement serveur. **Gardes** : 12 tests rouges d'abord, 7 mutations vues rouges, e2e parcours + cibles ; 1 580 unitaires.
