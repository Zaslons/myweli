- 🟡 **iOS : l'App Store lisait les deux apps comme anglaises — le projet passe au français et le paquet reçoit un `fr.lproj` ; l'iPhone ne tourne plus en paysage ; l'effet sur la fiche se lira sur le prochain build envoyé (mobile + docs, 2026-10-13).** Deux des trois décisions de [app-store-forms.md](../../design/app-store-forms.md) §13.1, prises par le propriétaire (« tout comme recommandé »). **Vérifié avant d'écrire** : sur le build 577, l'API d'App Store Connect rend `buildBundles.locales = ["en"]` ; dans son archive, la racine de `Runner.app` n'a qu'un dossier de langue, `Base.lproj`, et `CFBundleDevelopmentRegion` vaut `en` — le `developmentRegion` du projet, hérité du modèle Flutter. `CFBundleLocalizations = [fr]` ne suffisait donc pas : un ingénieur d'Apple l'écrit, la ligne « Langues » vient des dossiers `*.lproj`, et la base d'un projet Xcode est l'anglais. **Deux changements pour la langue**, parce que chacun seul est un pari sur ce qu'Apple lit : la langue de développement devient le français (`Base.lproj` est alors du français), et un vrai `fr.lproj` entre dans le paquet — un `InfoPlist.strings` sans aucune clé (une clé y écraserait `Info.plist`, dont les textes de permission varient par saveur). **Et le portrait seul sur iPhone** : aucun écran n'avait jamais été essayé en paysage ; l'iPad garde ses quatre orientations (le multitâche les exige ; seule l'app consommateur y tourne). Une seule cible et un seul `Info.plist` servent les deux saveurs : **MyWeli et MyWeli Pro changent ensemble**. **Gardes** : sept épingles dans `ios_store_readiness_test.dart`, écrites d'abord — trois rouges sur le projet d'avant (`developmentRegion` lu `en`, aucune référence à `fr.lproj`, trois orientations sur iPhone), quatre témoins ; le fichier de chaînes est suivi maillon par maillon (référence → groupe de variantes → fichier de build → phase « Resources » de `Runner`), parce qu'un dossier que la cible ne copie pas n'est pas dans le paquet. **14 mutations sur du code commité, 14 rouges.** **Sur le paquet construit** (simulateur, saveur Pro) : `CFBundleDevelopmentRegion = fr`, `Base.lproj` et `fr.lproj` à la racine, `UISupportedInterfaceOrientations = [Portrait]` ; les mêmes commandes, lancées sur l'IPA du 577, rendent bien `en`, trois orientations et `Base.lproj` seul — elles distinguent les deux états, et rejoignent la vérification de l'IPA (§11.3). **Trouvé en route** : `ios/tool/setup_flavours.rb` n'est plus sans effet quand on le relance — il recrée une phase de script sous un nouvel identifiant et réécrit les deux schémas sans ce que Flutter y a ajouté depuis ; la section « langue » a donc été appliquée seule, et le script entier n'a pas été relancé ([mobile-ios-flavours.md](../../design/mobile-ios-flavours.md) §6). L'enregistrement par `xcodeproj` a aussi retiré un objet orphelin (une seconde phase « Copy Firebase config » qu'aucune cible ne référençait). **Ce qu'aucun test ne montre** : la lecture d'Apple — `locales` doit valoir `["fr"]` sur le prochain build envoyé, sinon on ne le soumet pas (§11.5) ; et que l'app ne tourne plus, non observé sur le simulateur, à voir sur l'iPhone (§11.6). **Reste ouvert** : Android, dont le manifeste ne fixe aucune orientation ; et confirmer que le verrou vaut aussi pour l'app consommateur.
