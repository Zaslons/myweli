- 🟡 **MyWeli (client) : des « stories » de l’accueil gérées par MyWeli — la spec, avant tout code (documentation · backend · console · mobile · web · 2026-11-23 — BACKLOG B0.10, décision 170).** Branche `docs/managed-home-stories-spec`, créée depuis `main` (`d0a31d63`). Spec : [managed-home-stories.md](../../design/managed-home-stories.md). Documentation seule : aucun code, aucun build, aucune console.
  - **Pourquoi :**
    - A1 (#834, pas encore fusionnée) cache les trois stories de démonstration derrière `FeatureFlags.homeStories`, éteint ; le propriétaire a demandé qu’on les garde et que quelqu’un les gère (décision 170) ;
    - cette spec dit qui publie, ce qu’est une story, comment elle reste vraie, et dans quel ordre la rangée revient.
  - **Trois constats qui corrigent la demande :**
    - la console d’administration est en Flutter Web (`mobile/lib/main_admin.dart`, `deploy-admin.yml`), pas en Next.js : les écrans du personnel sont en Dart ;
    - aucune règle CORS du compartiment public de R2 n’autorise `admin.myweli.com` (le manifeste ne liste que `myweli.com` ; une demande préalable GET refusée le 2026-11-12, admin-remote-images.md §1.1 ; un PUT jamais sondé) : la console ne pourra téléverser une image qu’après une règle autorisant son PUT, un changement dans le cloud, sur le mot du propriétaire ;
    - le drapeau et ses gardes ne sont pas sur `main` : ils sont sur la branche d’A1.
  - **Ce que la spec propose :**
    - **qui publie :** le personnel de MyWeli, depuis la console ; les salons restent en V2 (PRD §7.2), avec les obligations des contenus d’utilisateurs (App Store 1.2, règle UGC de Play) ;
    - **une story :** un titre de 20 caractères, un texte facultatif de 140, une image portrait et sa vignette, sa description pour les lecteurs d’écran, un bouton vers un salon public ou une recherche, jamais une adresse libre, un début dans les 30 jours et une fin 30 jours au plus après, des communes, un ordre ; 8 au plus à la fois ;
    - **la règle de vérité :** ni prix ni réduction tant que la réservation ne peut pas les porter (App Store 2.3.1, « un prix faux, dans l’app ou hors de l’App Store » ; Play, déclarations trompeuses), aucun mot dessiné dans l’image ; celui qui publie écrit comment il sait que c’est vrai et coche une confirmation ; une story publiée ne se modifie plus ; le serveur cesse de la servir à sa fin, quand un salon qu’elle nomme n’est plus public, et dans la minute quand on la retire (un téléphone déjà ouvert la retire à sa prochaine lecture) ; ses images sont supprimées 90 jours après sa fin, ou tout de suite sur demande ;
    - **le backend :** une table (migration 0047), `GET /stories` public et sans paramètre, dix routes `/admin/stories*` auditées (publication sous verrou, ordre en compare-and-set), l’objectif d’envoi `story` sur `/uploads/sign` réservé à l’admin, dont la clé est revérifiée à la réclamation, le contrat, la menace T85 ;
    - **l’app :** une interface avec son mock et sa version API ; rien si c’est vide ou en erreur, un squelette pendant le chargement seulement si ce téléphone avait des stories la dernière fois (une exception à la règle des quatre états, Q10) ; la minuterie attend l’image, résiste à « Supprimer les animations » et s’arrête avec un lecteur d’écran ; la démo et ses SVG supprimés, puis le drapeau allumé dans sa propre PR ;
    - **le site :** la même rangée sur l’accueil de `myweli.com`, rendue avec la page puis revérifiée dans le navigateur par une route Next (le navigateur n’appelle jamais l’API) ;
    - **la vie privée :** la requête n’envoie ni commune ni identifiant ; rien à déclarer de plus si l’on ne compte pas les vues.
  - **Relue une fois par un lecteur indépendant, chargé de la réfuter :** 22 constats, chacun vérifié dans le code et intégré (entre autres : une image partagée par un doublon, un retrait qui n’atteint pas une app déjà ouverte, la clé d’image non revérifiée, la console qui ne peut pas dessiner l’aperçu avec `TimedCachedImage`, le site qui ne peut pas appeler l’API depuis le navigateur).
  - **Onze questions au propriétaire (§14), chacune avec une recommandation :** qui publie, les prix, le site, le cas sans commune, compter les vues, les 30 jours, la règle CORS, le drapeau dans sa propre PR, quand construire, l’exception aux quatre états, et combien de temps garder les images.
  - **Ce qui change :** [managed-home-stories.md](../../design/managed-home-stories.md), nouveau, et l’index des specs.
  - **Reste :** les réponses du propriétaire ; puis, chacune sur son mot, les PR B (backend), C (console), D et E (app), F (site), la règle CORS et chaque déploiement.
