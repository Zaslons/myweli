- 🟢 **Pro web — les notifications du navigateur : le salon prévenu sur son ordinateur, onglet fermé (web + backend, 2026-10-20).** ([web-pro-browser-push.md](../../design/web-pro-browser-push.md)) Le second canal de la décision « les deux, l'e-mail d'abord » (#649). **Ce qui change** : sur l'Accueil, une fois par navigateur, le bandeau « Activer les notifications » (la feuille de l'app à sa première visite) — « Activer » / « Plus tard », la question du navigateur seulement après « Activer » ; sur Notifications, « Notifications du navigateur » au-dessus d'« Alertes par e-mail », avec ses états (bloqué et comment rétablir, navigateur incapable, téléphone → l'app) ; la notification dit ce que dit le push de l'app et un clic ouvre la fiche dans le bon salon ; l'onglet ouvert relit le fil tout de suite ; à la connexion, un navigateur déjà autorisé se réinscrit ; **à la déconnexion, il se désinscrit d'abord** (l'ordinateur partagé d'un salon). Ordinateur seulement. **Le serveur** : les jetons portent leur plateforme ; **seul un push de l'app remplace l'e-mail** (FCM accepte un push vers un navigateur fermé — compté, il aurait fait taire l'e-mail) ; `webpush` urgent, un jour au plus. **Trouvé en construisant** : Firebase n'attend un service worker actif que s'il l'enregistre lui-même — le premier « Activer » aurait échoué (corrigé, gardé). **À faire par le propriétaire** : l'application Web Firebase dans le projet du compte de service `FCM_*`, la clé Web Push, les cinq variables Vercel, la clé d'API restreinte ; le serveur avant le web. **Dépend de** #649.
