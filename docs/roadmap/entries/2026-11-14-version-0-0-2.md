- 🟡 **La version 0.0.2 : une ligne de `pubspec.yaml`, pour l’App Store et Google Play (app · 2026-11-14 — BACKLOG B0.10, décisions 111, 119 et 134).** Non fusionné : branche `chore/version-0.0.2`, créée depuis `main` (`2aa2375f`). L’étape 3 (b) de [android-play-release.md](../../design/android-play-release.md) §4 : le changement de version, seul.
  - **Pourquoi :** la 0.0.1 est publiée sur l’App Store, qui n’accepte plus de build d’une version publiée ; le prochain build iPhone est donc la 0.0.2. Le premier build Android porte la même version (décision 111) : les deux apps viennent du même code et lisent leur version dans ce seul fichier.
  - **Ce qui change :** `version: 0.0.1+1` devient `version: 0.0.2+1`, rien d’autre dans le code. Le `+1` reste : `tool/release_build.sh` le remplace par le nombre de commits, et un test vérifie qu’il est toujours là. L’app client partage ce fichier et passe aussi en 0.0.2 ; elle n’a encore de fiche sur aucun store.
  - **Après la fusion :** plus aucune fusion sur `main` jusqu’au build iPhone 0.0.2, parce que le script construit la tête de `origin/main` (étape 3 (c)). Ce build se fait sur le feu vert du propriétaire (étape 3 (d)) ; son envoi à Apple attend son oui et les deux nouvelles questions de classification par âge.
