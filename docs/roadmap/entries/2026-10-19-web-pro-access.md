- 🟡 **Web — un salon trouve enfin son Espace Pro : « Espace pro » dans l'en-tête, un groupe « Professionnels » dans le pied de page, une bande sur l'accueil, la page publique `/professionnels`, un en-tête sur la connexion et l'inscription Pro, et le consentement CGU + confidentialité lié ; reste la CI (web + une ligne backend, 2026-10-19).** ([web-pro-access.md](../../design/web-pro-access.md)) **Le constat** : aucun lien du site public ne menait à `/pro` — alors que, depuis la voie compagnon, **le web est le seul endroit où un salon choisit son offre** ; `/pro/connexion` et `/pro/inscription` n'avaient ni logo ni retour au site (un test de préfixe `/pro` cachait tout, et aurait caché `/professionnels` aussi) ; l'inscription Pro web n'affichait **aucun** consentement (l'app, si), la connexion client un consentement **sans lien**. **Maintenant**, selon les lois de l'UX (Jakob : l'entrée pro en haut à droite ; Hick : deux choix ; von Restorff : une seule action pleine) : « Espace pro » dans l'en-tête à partir de 640 px, le groupe du pied de page et la bande « Vous êtes un salon ? » pour les téléphones ; **`/professionnels`** — rendue côté serveur, indexable, six avantages qui existent aujourd'hui (le texte des fiches de store), trois étapes, une FAQ avec son `FAQPage`, **aucun prix** (décision du propriétaire), dans le sitemap et `llms.txt` ; un en-tête minimal (logo → accueil, « Espace pro ») sur les pages de connexion Pro ; `LegalConsentText` (les deux documents liés) sur l'inscription Pro, la connexion Pro et la connexion client ; une session Pro valide qui ouvre `/pro/connexion` va droit au tableau de bord. **Backend** : `professionnels` réservé comme slug de salon, et **un test tient chaque route de premier niveau du web dans la liste réservée**. **Vérifié ici** : 1 641 tests unitaires web, backend vert, le parcours dans le navigateur à 1280 et 375 px. **Avant le déploiement serveur** : vérifier qu'aucun salon n'a déjà le slug. **Empilé sur** la PR des notifications Pro.
