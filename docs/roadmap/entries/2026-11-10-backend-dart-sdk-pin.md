- 🟢 **Le SDK Dart du serveur est épinglé au plancher de l’avis TLS GHSA-frr6-h895-5pxp, et la CI teste enfin avec le compilateur qui part en production (backend + CI · 2026-11-10).** Non fusionné. **L’avis, lu :** huit certificats *intermédiaires* eMudhra compromis permettent de forger un certificat pour n’importe quel domaine ; `dart:io` vérifie avec le BoringSSL compilé dans le binaire, et 3.13.7 ajoute à `X509_verify_cert` une liste de blocage des huit clés (BoringSSL `dd682072baab`) — indépendante du magasin de racines. Sur Linux, ce magasin est le fichier `/etc/ssl/certs/ca-certificates.crt` de l’image `scratch`, figé au build de l’image de base ; il fait **toujours** confiance aux trois racines emSign d’eMudhra, y compris dans la dernière `dart:3.13.7` (octet pour octet identique) — « rafraîchir le bundle » ne corrige donc rien aujourd’hui, le SDK si. **La production, lue sans rien modifier :** `myweli-api-00048-9f4` à 100 %, image `4e78e48` (`sha256:a9c536…`), construite le 2026-11-03 depuis `dart:stable` → **3.13.7**, lu dans le binaire lui-même ; le témoin : `00046-bzg` lit **3.13.6**. La production a donc tourné avec un vérificateur vulnérable jusqu’au 2026-10-25 22:43Z (~52 h après l’avis) ; une exploitation n’est ni prouvée ni vérifiable d’ici. Elle était corrigée **par le hasard du calendrier** : `FROM dart:stable` flottait, le commentaire du Dockerfile conseillait d’épingler `dart:3.10` (vulnérable), et la CI compilait en 3.10.7. **Le correctif :** `FROM dart:3.13.7@sha256:854f3c50…` (le digest que la dernière image utilise déjà), `dart_frog_cli 1.2.14` comme la CI, les deux jobs backend de la CI en 3.13.7, Dependabot `docker` sur `/backend`, un plancher de retour arrière dans [infra-rollback.md](../../design/infra-rollback.md) §0, la menace **T81**. **Ce que 3.13.7 a trouvé :** six fichiers de test reformatés, et un vrai défaut — `MessagingService.sendTemplate` renvoyait `_outbox.append(…)` sans `await` dans son `try`, donc un échec d’écriture de l’outbox **traversait** le `catch` qui promettait « ne lève jamais » ; prouvé rouge par un test avant le correctif (sans effet en production : la messagerie y est désactivée). **Deux gardes, parce que la première lit une étiquette et que Docker construit un digest :** `dart_sdk_pin_test` (9 tests, à chaque PR) et, à chaque déploiement, entre le build et `replace`, `verify-image-dart-sdk.sh`, qui lit la version **dans le binaire construit** et refuse tout ce qui est sous 3.13.7 — y compris la promotion d’une vieille étiquette, le seul chemin qui ne construit rien. Exécuté ici en lecture seule sur de vraies images : `4e78e48` passe, `eca4db6` (3.13.6) est refusée, `45a5d0f` passe. **Et ce passage a trouvé autre chose :** depuis que `ubuntu-latest` est passé en 26.04, chaque build pousse un **index OCI** (image amd64 + attestation) ; la production sert un manifeste Docker v2 classique ; la première version du script refusait ce dernier build (et, selon toute vraisemblance, tous ceux du runner 26.04), et Cloud Run n’a encore jamais servi d’index ici — non vérifié, puisque le staging est absent. Mutations regardées rouges dans le message de commit. Backend complet en 3.13.7 : format propre, analyze 0, 2073 tests.
