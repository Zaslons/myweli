- 🟢 **Pro — sur une coupure, l'état d'erreur dit « Pas de connexion. Réessayez. », comme l'app ; un 5xx garde sa phrase ; le sélecteur de salon le dit sur les deux plateformes (web + mobile Pro, 2026-10-16).** ([web-pro-no-connection-copy.md](../../design/web-pro-no-connection-copy.md)) **Le constat** : depuis #619, une coupure réseau mène chaque page Pro web à son état d'erreur et à « Réessayer », mais avec « Une erreur est survenue. Réessayez. » (ou la phrase propre de la page : « Impossible de charger les avis. », « Chargement impossible. »…), là où l'app nomme le réseau ; et le sélecteur de salon — web **et** app — disait « votre accès à ce salon a peut-être été retiré. » pour toute erreur, réseau compris. **La décision** : chaque page garde *pourquoi* sa lecture a échoué — `LoadFailure | false` (`'offline' | 'failed'`, le vocabulaire de `logoutPro`) là où elle gardait un booléen ; seuls les `setError(true)` changent, et le compilateur les trouve tous. Le statut 0 (rien d'utilisable n'est revenu au navigateur) → « Pas de connexion. Réessayez. » (`NO_CONNECTION_MESSAGE`) ; tout autre échec → la phrase de la page, ou la valeur par défaut d'`ErrorState`, **inchangée**. Un 5xx du BFF (l'API injoignable) n'est pas « Pas de connexion » : la connexion de la personne marche. Les 16 pages, la Journée, le sélecteur web (`switchSalon` → `'switched' | LoadFailure`). **Le sélecteur, décision A du propriétaire** (« web and app both say « Pas de connexion. Réessayez. » when there is no answer ») : côté app, la sonde `getMyProvider` sans réponse porte `code: 'network'` (là seulement — les 28 autres appels gardent le leur), `ProAuthProvider.switchSalonOutcome` dit `switched` / `offline` / `refused`, `switchSalon` garde son booléen pour ses autres appelants, la feuille choisit la phrase. **Vu en relisant l'app** : elle a deux phrases pour une coupure (« Pas de connexion. Réessayez. » et « Connexion au serveur impossible » dans `api_pro_service`, `_auth_`, `_appointment_`) — le web n'en dit qu'une ; les aligner est consigné. **Vu rouge** : 31 cas web (les 16 pages sans réseau, 11 lectures propres coupées, « Charger plus », une période des Revenus, la Journée), 2 pour le sélecteur web, 3 pour l'app ; une **table 5xx** neuve, verte avant comme après, garde la phrase par défaut ; deux tests de #616 qui épinglaient la phrase générique sur une coupure sont tombés rouges et attendent maintenant la bonne. **Mutations** : 27 sur 27 (pages), 5 sur 5 (sélecteur web), 6 sur 6 (app). **Déploiement** : le web au merge, après #619 ; l'app avec le prochain build ; rien côté serveur.
