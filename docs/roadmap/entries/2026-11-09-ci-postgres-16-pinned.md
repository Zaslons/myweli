- 🟢 **Les deux jobs backend de la CI tournent de nouveau sur PostgreSQL 16 : ils épinglent `ubuntu-24.04` (CI · 2026-11-09).** Fusionné le 2026-11-09 (`84d43a55`, #752) ; sur `main`, les deux jobs backend sont verts sur ce commit (run 42673406543). Rien n'est déployé côté backend ; Vercel a reconstruit le web, dont l'arbre `web/` est inchangé. **Le défaut, observé** : depuis le 2026-11-07, chaque PR vers `main` échouait à « Backend — Analyze & Test » et « Backend — boot smoke + funnel e2e », à l'étape qui démarre PostgreSQL, avant le moindre test : les PR Dependabot du 7 novembre (run 42415764210) puis #751 (run 42662619408). `ubuntu-latest` passe à Ubuntu 26.04 (actions/runner-images#14748, migration du 19 octobre au 19 novembre 2026), dont l'image installe PostgreSQL 18. Le garde-fou de `.github/scripts/start-postgres.sh` l'a refusé, à raison : la production est Cloud SQL PostgreSQL 16. Dernier vert : run 42237489244 du 6 novembre, image `ubuntu-24.04`, PostgreSQL 16.15. Tous les autres jobs de #751 étaient verts. **Le correctif** : les deux jobs qui appellent le script épinglent `runs-on: ubuntu-24.04`. Vérifié dans `actions/runner-images` : une image installe la version majeure que nomme son toolset. Celui de 24.04 dit 16 dans chacune de ses 71 versions depuis sa création (2024-04-26) ; celui de 26.04 dit 18. Aucun téléchargement n'est ajouté : la raison d'être du script (#612, les images tirées limitées par IP) tient toujours. Le garde-fou ne change pas (`WANT_MAJOR=16`) ; son message nomme maintenant l'image du runner, que l'échec du 7 novembre ne montrait que dans le journal de démarrage du job. **L'option écartée, mesurée** : installer 16 depuis apt.postgresql.org sur `ubuntu-latest` (26.04) marche, en 14 s pour 16.15, mais pas tel quel. `apt-get install postgresql-16` n'y a créé aucun cluster (la raison n'est pas établie : `create_main_cluster` reste à sa valeur par défaut), et le script a échoué sur « localhost:5432 - no response ». Il faut supprimer le cluster de l'image, qui tient le port 5432, puis lancer `pg_createcluster 16 main --port 5432` ; le garde-fou passe alors. C'est surtout un téléchargement à chaque run, ce que le script a été écrit pour éviter. Elle reste la sortie quand 24.04 sera retirée, ou si la production passe à une version majeure qu'aucune image n'installe ; l'en-tête du script donne la recette. Les deux horizons se valent : PostgreSQL 16 n'est plus maintenu après novembre 2028, et selon la règle publiée de GitHub (deux images GA au plus), le retrait de 24.04 ne commencera qu'à la sortie de 28.04 — une déduction de cette règle, pas une date annoncée. **Vu rouge** (runs scratch 42668615710 et 42668938372, branche supprimée depuis) : `WANT_MAJOR=15` sur 24.04, la mutation prouvée appliquée (`32:WANT_MAJOR=15`) → « The runner's PostgreSQL is 16 (server_version_num 160015, runner image ubuntu24 20261101.360.1); production is 15 ». Le script réel sur `ubuntu-latest` → rouge sur 18 (image ubuntu26 20261101.186.1). Vert : le script réel sur 24.04, PostgreSQL 16.15. Les PR ouvertes avant la fusion (dont celles de Dependabot) ne prennent le correctif qu'après un rebase.
