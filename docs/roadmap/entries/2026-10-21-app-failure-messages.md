- 🟢 **L'app dit la bonne chose quand quelque chose échoue — plus de texte d'exception, une seule phrase hors ligne (app + web, 2026-10-21).** ([app-failure-messages.md](../../design/app-failure-messages.md)) Le lot 3 du [BACKLOG](../../BACKLOG.md), PR A (B3.1 + B3.2). **Avant** : un Wi-Fi à portail captif (du HTML en 200) faisait afficher « FormatException: Unexpected character… » — 73 `e.toString()` dans 23 fournisseurs ; un code inconnu disait « Erreur » ; quatre phrases disaient « rien n'a répondu » (« Connexion au serveur impossible », « Connexion impossible. Réessayez. », « Pas de connexion. Réessayez. », « Erreur serveur (500) ») ; sur le web, un enregistrement hors ligne disait « L'enregistrement a échoué ». **Ce qui change** : deux aides partagées dans l'app (une réponse illisible est « Une erreur est survenue. Réessayez. », un refus dit la phrase de son code — jamais « Erreur », jamais le `message` du serveur) ; **« Pas de connexion. Réessayez. » partout** quand rien n'a répondu, avec le code `network` ; la carte dit « Position introuvable. Réessayez. » ; sur le web, huit enregistrements et cinq lectures client disent « Pas de connexion » hors ligne (`loadFailure` passe dans `lib/api`). **Trouvé en construisant** : un défaut du lot 1 en production — « Accueil » ne disait jamais « Pas de connexion », le vrai service n'envoyant pas le code que ses tests (un faux) envoyaient. **Gardes** : rouges d'abord, des épingles sur l'arbre entier (aucun `e.toString()` dans les fournisseurs et écrans, aucune ancienne phrase, aucun « Erreur » seul, aucun `message` du serveur) ; mutations vues rouges — app 12, web 13. **L'app** atteint les personnes par la prochaine version des stores. **À suivre** : PR B (B3.3, l'état « lu » des notifications, décision 12).
