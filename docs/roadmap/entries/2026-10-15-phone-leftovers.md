- 🟢 **Téléphone, les restes — une faute dit `invalid_phone` partout, un champ du mauvais type répond 400 et plus 500, et le numéro d'une fiche client se modifie, son historique avec (backend + app + web, 2026-10-15).** Ce que [phone-national-length.md](../../design/phone-national-length.md) avait laissé (§11) et ce que sa revue avait écarté (§12), traité d'un tenant ([phone-leftovers.md](../../design/phone-leftovers.md)). **Codes** : l'inscription Pro, le profil du salon, l'acompte et les OTP verify répondaient `invalid_input` pour un téléphone — les clients ne pouvaient pas mettre la faute sous le bon champ (« Numéro ou code invalide. » sur un écran sans code) ; ils disent `invalid_phone` (et `invalid_whatsapp` pour le WhatsApp du profil), et l'app comme le web la placent sous le champ. **400, pas 500** : `body['x'] as String?` levait sur un nombre et le middleware le prenait pour une panne serveur (500, rapport d'erreur) — 66 lectures dans 27 routes ; elles passent par `optionalString`/`optionalList`, et un champ du mauvais type répond 400 `invalid_body` sans rapport ; un `TypeError` ordinaire reste un 500 rapporté ; une épingle interdit le retour d'un `body[…] as` dans les routes. **Web** : « Réserver » et « Mon compte » parlent sous le champ au lieu de griser le bouton ; l'Acompte garde son numéro quand les dépôts sont désactivés (comme l'app) ; un numéro de client choisi refusé mène à sa fiche ; trois formulaires ne disent plus « Numéro invalide » pour un échec réseau. **App** : le masque des écrans OTP n'a plus de longueur +225 en dur ; `maskClientPhone` lisait « +336 … » pour un numéro français. **Le numéro d'une fiche client** (décisions du propriétaire) : une fiche invitée retrouve ses visites par son numéro — le changer emporte, dans la même transaction, les rendez-vous manuels de CE salon sur l'ancien numéro (jamais un autre salon, T45) ; une fiche liée à un compte garde le numéro du compte (lecture seule) ; un numéro déjà sur une autre fiche est refusé avec un lien vers elle ; et — décidé en construction, au nom de T48 — la fiche anonymisée d'un compte effacé ne prend aucun numéro. App : une feuille sous le numéro ; web : un `Modal`. **Vu rouge** : chaque test nouveau ou modifié d'abord contre l'ancien code ; plus de 40 mutations attrapées sur les trois surfaces. **Déploiement : le serveur avant l'app.**
