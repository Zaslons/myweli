- 🟢 **Acompte — désactiver les acomptes n'efface plus l'opérateur ni le pourcentage, et 0 % veut dire « pas encore choisi » (web + app, 2026-10-16).** ([acompte-off-parity.md](../../design/acompte-off-parity.md)) **Le défaut** : `PUT /providers/{id}/deposit-policy` remplace la politique entière, et le web envoyait `mobileMoneyOperator: null` et `depositPercentage: 0` dès que l'interrupteur était sur « non » — l'opérateur et le pourcentage étaient effacés. Or la lecture d'un rendez-vous sert l'opérateur **actuel** du salon : un client qui devait encore son acompte perdait le nom de l'opérateur et le lien « Payer avec Wave ». L'app, elle, envoie ce qu'elle tient. **Le 0 %** : tout nouveau salon est créé à 0 % (et le web en écrivait d'autres) ; l'app affichait « 0 % » avec le curseur dessiné à 5 %, et activer puis enregistrer était refusé — « Informations invalides. ». Décision du propriétaire : 0 % = pas encore choisi, les deux formulaires proposent 30 % (`kDefaultDepositPercentage` ↔ `DEFAULT_DEPOSIT_PERCENT`, gardés d'accord par un test croisé) ; aucune migration, aucun changement serveur. **Web, en plus** : un chargement refusé (403, 5xx) affichait un formulaire vierge dont l'enregistrement écrasait la vraie politique, et une coupure réseau laissait le chargement tourner pour toujours — dans les deux cas c'est maintenant l'`ErrorState` et « Réessayer », comme l'app ; un enregistrement sans réseau laissait « Enregistrer » désactivé pour toujours ; le champ refuse sous 1 % comme son message le dit, et au-delà de deux décimales ; un pourcentage choisi est relu au centième, pour qu'un enregistrement intouché réécrive ce qu'il a lu. **App, en plus** : l'opérateur n'était pas vérifié — acomptes activés sans opérateur, le serveur refusait et l'écran disait « Informations invalides. » ; c'est « Choisissez un opérateur Mobile Money. » sous les puces, et l'appui y ramène. **Vu rouge** : chaque test d'abord contre l'ancien code ou sous mutation ; 18 mutations sur 18 rattrapées sur deux passes (spec §8) ; l'e2e (désactivé → enregistré → rechargé → réactivé) rouge sous le D1 d'origine. **Hors périmètre, consigné** (§7) : les plages 5–80 % (app) / 1–100 % (web) ; l'étape « Acompte » de l'accueil Pro qui se coche pour tout salon ; 15 autres écrans web Pro qui tournent pour toujours sur une coupure réseau (proposés comme tâche à part). **Déploiement** : le web au merge ; l'app au prochain build ; rien côté serveur.
